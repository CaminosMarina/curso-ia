## Problemas frecuentes

| Síntoma | Causa probable | Solución |
|---|---|---|
| `local.py`: error de conexión | Ollama no está corriendo | Abrí la aplicación Ollama, o ejecutá `ollama serve` en otra terminal |
| `local.py`: "model not found" | El modelo no está descargado o el nombre no coincide | `ollama list` muestra los modelos descargados; `ollama pull llama3.2` lo descarga |
| `api.py`: error de autenticación o de clave inválida | El `.env` no se cargó, o la clave tiene espacios o comillas | Ejecutá con `--env-file .env` y revisá que la línea sea exactamente `GEMINI_API_KEY=` seguido de la clave |
| `Failed to read environment file` … `did not contain valid UTF-8` | El `.env` se creó desde PowerShell con `>` y quedó en UTF-16 | Borralo y crealo de nuevo con tu editor, guardado como UTF-8 |
| `api.py`: error de modelo no encontrado | El nombre del modelo cambió | Usá el modelo que indique la [guía oficial](https://ai.google.dev/gemini-api/docs/quickstart) |
| `api.py`: error de cuota o "resource exhausted" | Superaste el límite de llamadas del nivel gratuito | Esperá unos minutos; los límites se renuevan |
| `.env` aparece en `git status` | El archivo se llama distinto (por ejemplo `.env.txt`) o falta el `.gitignore` en la raíz | Revisá el nombre con `ls -a` (Bash) o `Get-ChildItem -Force` (PowerShell) |
| `gitleaks git` encuentra un secreto | Una clave entró en algún *commit* | Revocá esa clave en la consola del proveedor y creá otra. Después podés limpiar el historial, pero revocarla es lo que importa |
