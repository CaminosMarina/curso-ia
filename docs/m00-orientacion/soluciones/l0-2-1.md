## Práctica

**Resultado del ejercicio.** `git ls-files` muestra algo parecido a esto (sin nada dentro de `.venv/`):

```text
.gitignore
README.md
apuntes/entorno.md
practicas/m00-hola/.python-version
practicas/m00-hola/README.md
practicas/m00-hola/main.py
practicas/m00-hola/pyproject.toml
practicas/m00-hola/uv.lock
```

Y `git check-ignore -v practicas/m00-hola/.venv` muestra la regla del `.gitignore` de la raíz:

```text
.gitignore:20:.venv/	practicas/m00-hola/.venv
```

El número de línea puede variar si editaste el archivo.

## Problemas frecuentes

| Síntoma | Causa probable | Solución |
|---|---|---|
| `uv`, `git` o `java` "no se reconoce como comando" | La terminal se abrió antes de instalar | Abrí una terminal nueva. Si sigue, reiniciá la sesión de Windows |
| `.venv/` aparece en `git status` | Falta el `.gitignore` en la raíz o se guardó con otro nombre (por ejemplo `.gitignore.txt`) | Revisá con `ls -a` (Bash) o `Get-ChildItem -Force` (PowerShell) |
| `.venv/` quedó versionado | Se hizo el *commit* antes de tener el `.gitignore` | `git rm -r --cached practicas/m00-hola/.venv` y un nuevo *commit*. El entorno no se borra del disco |
| `uv init` creó una carpeta `.git` dentro de la práctica | Faltó `--vcs none` | Borrá esa carpeta `.git` interna (no la de la raíz) |
| Docker: "WSL 2 installation is incomplete" o el motor no arranca | WSL 2 o la virtualización no están activados | Seguí el enlace que muestra Docker Desktop para actualizar WSL; si persiste, revisá en la BIOS que la virtualización esté activada |
| `docker: command not found` o "cannot connect to the Docker daemon" | Docker Desktop no está abierto | Abrilo y esperá a que indique que el motor está corriendo |
| Linux: "permission denied" al usar `docker` | Tu usuario no está en el grupo `docker` | Usá `sudo docker …` o seguí los [pasos posteriores a la instalación](https://docs.docker.com/engine/install/linux-postinstall/) |
